# 추출 정확도 개선 — 공급가 기본값, 카테고리/브랜드 분리, 재고 판정, 배송비 범위

## 배경

걸스굽/시즌백/신우 등 실제 도매몰 데이터를 하나씩 열어보며 추출 로직의 구조적 오판을 여러 건 발견했다.
전부 "몰마다 상품페이지 구조가 다르고, 같은 몰 안에서도 상품마다 다르다"는 이 코드베이스의 전제 위에서,
실제 페이지를 먼저 열어 근거를 확인한 뒤 고쳤다.

사용자가 확인해준 사실들:
1. 이런 도매/공급 몰에서 단일 가격만 있으면 그건 소비자판가가 아니라 **공급가(원가)**다 — 페이지가
   명시적으로 소비자가/오픈마켓가/정상판매가라고 라벨링한 경우에만 `price`(소비자판가)로 봐야 한다.
2. 시즌백처럼 카테고리 트리에 "브랜드"라는 노드가 있고 그 아래 브랜드명(OZUKO 등)이 자식으로 있는 몰이
   실제로 있다 — 이 경우 브랜드명이 `카테고리`로 잘못 들어가고 있었다.
3. 신우 한 상품에서 카테고리명 누락, "3,000~4,000원" 배송비 범위를 4000으로 잘못 파싱, 옵션1→옵션2 AJAX
   캐스케이드로 실제 선택 가능한 옵션이 있는데도(=재고 있음) 품절로 표시되는 3가지 문제를 확인.

## 설계

일반모드(`lib/extract.ts`)와 개발자모드(`extension-poc/background.js`의 `buildExtractExpr`)는 거의 같은
휴리스틱을 독립적으로 구현하고 있어, 아래 각 수정은 **양쪽에 동일하게 반영**했다(드리프트 방지).

### 공급가 우선, 소비자판가는 명시적 라벨이 있을 때만

`costPrice`를 `const`에서 `let`으로 바꾸고 우선순위를 재구성:
- `labeledRetailPrice`(정규식 `/소비자가|시중가|오픈마켓|정상\s*판매\s*가|정상가/`로 라벨을 찾은 값)가
  있으면 **무조건** `price`로 확정(ld+json보다도 우선 — 페이지 자체 표기가 가장 신뢰도 높음).
- 그 외의 일반 가격 스캔(클래스명 기반, 숨은 `#price` input 등)은 전부 `costPrice`로 배정하고,
  `price == null && costPrice == null`일 때만 시도.
- 결과적으로 라벨 없는 단일 가격 몰은 `price`가 비고 `cost_price`만 채워진다 — 이게 정상.

### 카테고리/브랜드 분리 — "브랜드" 노드 인식

카테고리 경로를 `textContent.split('/')` 같은 naive 문자열 분리 대신 실제 `<li>` 요소 단위로 읽고, 각
항목을 `.replace(/^[\s/]+|[\s/]+$/g, '')`로 앞뒤 슬래시/공백을 제거한다(시즌백 "SANDAL/MULE"처럼 상품명
자체에 슬래시가 있는 경우와 구분하기 위해 요소 단위로 분리). `<li>` 목록에서 텍스트가 "브랜드"인 노드를
찾으면, 그 바로 다음 항목을 카테고리가 아니라 `brand`로 분리해 담는다.

추가 폴백(신우 케이스 — 브레드크럼에 카테고리가 아예 없는 경우): `.productCategory .state h3`에서 상위
카테고리명을, `.productCategory .detailCate a[href*="cat_code="]`에서 현재 페이지 URL의 `cat_code` 파라미터
와 일치하는 링크를 찾아 하위 카테고리명을 얻어 `"${parent} > ${sub}"`로 조합.
(`background.js` 쪽은 자기 자신이 하나의 backtick 템플릿 문자열이라, 여기서 다시 `` `${a} > ${b}` `` 같은
중첩 템플릿 리터럴을 쓰면 바깥쪽 템플릿이 안쪽 `${}`를 먼저 소비해버려 원격 실행 문자열 자체가 깨진다 —
`a + ' > ' + b` 문자열 연결로 대체.)

### 재고 판정 — AJAX 캐스케이드가 body 텍스트 스캔보다 우선

`option1` 선택 시 `option2`가 실제로 채워지는지(=주문 가능한 조합이 실재하는지)를 먼저 확인하고, 그
결과가 확정적이면(`cascadeStockKnown`) 그걸로 재고 여부를 결정한다. 캐스케이드로 판단 못 할 때만 기존의
본문 텍스트 `/품절/` 스캔으로 대체한다 — "품절 시 교환/환불 불가" 같은 정책 안내 문구가 실제 품절 표시로
오탐되는 문제가 있었기 때문에, 캐스케이드가 있으면 그게 항상 이긴다.

### 배송비 — 범위 표기의 낮은 쪽을 취함

`firstNumber`가 숫자 하나만 찾던 것에, 범위 패턴을 먼저 검사하는 로직을 추가:
`text.match(/([\d,]{2,})\s*~\s*[\d,]{2,}\s*(?=원)/)`로 "3,000~4,000원"을 만나면 **낮은 쪽**(3000)을
반환하고, 범위가 없으면 기존 단일 숫자 로직으로 폴백.

### 재고 판정 오탐 방지 — 숨은 요소 제외

와일드카드 클래스명으로 재고 관련 요소를 스캔하던 로직에 `offsetParent !== null` 필터를 추가해, 화면에
안 보이는 요소(네비게이션 드롭다운 패널 등 우연히 같은 클래스명 패턴에 걸리는 것)를 제외한다.

## 하지 않는 것 (알려진 한계)

- 라벨 정규식·클래스명 패턴은 지금까지 실제로 마주친 몰 표기만 반영한다 — 새로운 표기 방식(예: 다른
  단어의 소비자가 라벨)은 또 나오면 그때 추가한다.
- 이번 수정은 코드 안에 하드코딩된 휴리스틱이다. 몰별 예외가 계속 늘어나면 "스크랩 조정"
  ([[scrape-adjustment]]) 쪽 학습 규칙으로 옮기는 게 맞지만, 지금은 아직 코드 레벨 수정.

## 관련 파일

- `lib/extract.ts`: `firstNumber` 범위 파싱, `costPrice`/`labeledRetailPrice` 우선순위, 카테고리 `<li>`
  스캔 + "브랜드" 분리 + `.productCategory`/`.detailCate` 폴백, `RawPageData.brandFromCategoryDetail`,
  재고 `offsetParent` 필터, `brand` 필드 우선순위
- `lib/scraper.ts`: `CategoryLabel { category, brand }`, `detectCategoryLabel`, `categoryByUrl` 타입 변경,
  bot-detection 오탐 방지(`cost_price` null도 같이 체크)
- `extension-poc/background.js`: `COLLECT_LINKS_EXPR`(카테고리/브랜드 분리), `buildExtractExpr`(가격/배송비/
  카테고리/재고 로직 전부 미러링, 중첩 템플릿 리터럴 버그 수정)

## 상태

**구현 완료.** 커밋 `3500f61`. 걸스굽 41건, 시즌백 66건(브랜드 분리) + 33건(정상판매가), 신우 실제 데이터로
검증 후 각각 미확정(pending) 스테이징 행에 한해 소급 반영(이미 병합된 production 행은 건드리지 않음).
`extension-poc/background.js`는 실제 처리된 런타임 문자열을 `new Function()`으로 재검증해 문법 오류 없음을
확인.
