# 참고 아키텍처: 도매의신 "상품DB다운" 페이지 분석

**호출 힌트: `/참고-도매의신`** — PTP의 마켓별 업로드 데이터 생성 기능을 개발할 때 이 문서를 참고할 것.

## 배경

도매의신(domesin.com)은 공급사 상품을 모아 파는 B2B 도매 플랫폼이자, 회원(셀러)이 그 상품들을 자신이 파는
여러 오픈마켓/솔루션 형식에 맞춰 대량 다운로드할 수 있는 "상품DB다운" 기능을 제공한다. 이건 PTP가 지금
만들려는 것("스크랩/마이그레이션한 상품마스터 → 오픈마켓별 업로드 양식 변환")과 **개념적으로 거의 동일한
문제**를 이미 풀어놓은 참고 사례라, UI/설정 구조를 참고용으로 남겨둔다.

- 원본: https://www.domesin.com/index.html?p=my/down3.html (로그인 필요, 2026-07-25 분석, 계정 `ilda`)
- 분석 방법: firecrawl_interact로 로그인 후 페이지 접근성 트리(accessibility tree) 전체를 텍스트로 추출

## 구성 (5개 구분)

### 1. 회원/현황 정보
등급, 적립금, 주문/클레임/문의 현황 — 다운로드 설정과 무관, 참고 가치 없음.

### 2. 기본설정 — "어떤 형식으로 뽑을지"
- **세트명**: 이전에 저장한 필터+설정 조합 불러오기(직접 입력 불가, 불러오기 전용) — PTP로 치면 "저장된 변환 프로필" 개념
- **솔루션 선택**(라디오, 택1): 플레이오토 XML / 플레이오토 엑셀 / 이셀러스 엑셀 / 샵링커 엑셀 / 스마트스토어 / 메이크샵 / 도매꾹
  - 플레이오토/이셀러스처럼 그 자체가 "여러 마켓에 재배포하는 멀티채널 솔루션"인 것과, 스마트스토어/메이크샵처럼 특정 마켓 직접 양식인 것이 섞여 있음 — PTP의 `Marketplace` 타입(coupang/naver/11st/gmarket/auction/shoplinker/sabangnet)과 레이어가 다르다는 점 주의(도매의신 쪽 "샵링커"는 최종 목적지, "플레이오토"는 중간 유통 솔루션)
- **마켓 아이디**: 옥션/지마켓/롯데ON/11번가/카카오톡스토어/인터파크/위메프2.0/스토어팜/티몬/쿠팡/도매꾹 — 각 마켓별 판매자 아이디를 콤마로 입력. 멀티채널 솔루션(플레이오토 등) 선택 시 마켓ID 매핑용으로 추정
- **파일당 상품수**: 100/300/500/1000/2000/5000개 — 대용량은 분할 저장(PTP `chunkBySize`/`max_batch_size`와 동일한 개념, 이미 구현돼 있음)
- **엑셀 내 DB파일 배치**: 랜덤 / 순차적

### 3. 상품 필터링 — "어떤 상품을 포함할지"
기간(등록일/수정일 × 기간), 카테고리(대분류 다중+제외), 쿠폰/반품쿠폰 제공, 도신배송 여부, 의료기기/건강기능식품
제외(신고증 필요), 가격 범위, 공급사코드(포함/제외), 주문이행률/출고속도/문의응답률(신뢰도 등급), 베스트/기획전
상품코드 불러오기, 상품코드/검색어 지정, 해외직배송, 원산지, 과세여부, 반품가능여부, 가격준수여부, 배송타입,
배송비/반품배송비 조건, 옵션여부, 성인여부, 상품상태, 추천옵션(옥션/지마켓 최적화 옵션 포맷).

→ PTP 쪽에서 참고할 부분: "어떤 상품을 이 배치에 포함시킬지"를 세밀하게 거르는 필터 세트가 실제로 셀러들에게
필요하다는 신호. 지금 PTP `generateExcel()`은 넘어온 `products` 배열을 그대로 다 내보내는 구조라, 향후
카테고리/가격대/재고상태 등으로 내보내기 전 필터링하는 UI가 필요할 수 있음.

### 4. 판매가 설정 — "마진 붙이는 방식"
- 판매가 계산해보기(시뮬레이션): 표준샘플가격 → 즉시할인%/할인율%/정액할인원/마진율%/수수료율% → 마켓판매가
- 마켓 판매가 설정: **가격대 구간(최대 10단계)별로 다른 마진율/수수료율** 적용 가능, 구간 밖은 전체 기본값

→ PTP `lib/pricing.ts`의 `computePricing()`이 지금 `MarketplaceConfig` 하나로 고정 마진율/수수료율만 계산하는
구조인데, 도매의신은 **가격 구간별로 다른 마진율**을 적용한다 — 저가 상품과 고가 상품에 같은 %를 적용하면
안 맞는 경우가 실제로 있다는 뜻. PTP 가격 로직 확장 시 참고할 것.

### 5. 기타 설정 — "후처리/부가 옵션"
개인정보동의 이미지 노출, 사용자 분류명(+구분번호), 상품명/상품코드 앞뒤 추가문구, 상세설명 상단/하단 HTML
추가문구, 상품명/상품정보고시 상세설명 자동삽입, 반품/교환 배송비 표시 여부, 홍보문구(20자 제한), 고객센터
연락처(마켓별 필수 여부 다름 — 예: 스마트스토어는 필수), 세트 저장(현재 설정 이름 붙여 재사용).

→ "세트 저장/불러오기"는 PTP의 `configs: Record<string, MarketplaceConfig>` 개념과 비슷하지만, 도매의신은
필터+포맷+가격+후처리 전체를 하나의 "세트"로 저장한다 — PTP도 마켓별 export 설정을 세트 단위로 저장/재사용하게
할지 고려해볼 만함.

## 보충: 공식 튜토리얼 영상 (1편)

[위탁배송 상품, 이렇게만 다운로드하면 성공한다.(도매의 신 상품DB 다운로드 1편)](https://www.youtube.com/watch?v=CyCJkgPM1NY)
(도매의 신 공식 채널, 2020-08-14, 14:28) — 위 화면 필드들을 실제로 왜/어떻게 쓰는지 실사용 노하우 설명.
**주의: 제목에 "1편"이라 명시돼 있고, 영상이 해외직배송/원산지/과세여부 지점에서 "2부에서 이어서"로 끊긴다 —
판매가 설정·기타 설정 구간을 다루는 2편은 아직 못 찾음(2부 추가로 찾으면 이 문서에 보충할 것).**

실사용 노하우 중 위 화면 분석만으로는 안 보였던 것들:

- **XML이 엑셀보다 편함**: 플레이오토처럼 멀티채널 솔루션을 쓸 경우, 엑셀로 받으면 파일을 다시 그 솔루션에
  업로드해야 하지만, XML로 받으면 URL 주소 형식이 나와서 그 URL을 솔루션에 그대로 복사-붙여넣기만 하면 끝난다.
  그래서 "엑셀" 대신 "XML"을 고르는 실사용자가 많다는 것 — PTP가 마켓/솔루션 export를 만들 때도 파일
  다운로드뿐 아니라 "재사용 가능한 URL(또는 API 피드)" 방식을 옵션으로 고려해볼 만함.
- **마켓 아이디 필드의 진짜 목적**: 단순 표기용이 아니라, **입력한 마켓에 한해서만 도매의신이 그 마켓의
  카테고리 체계에 맞춰 상품 카테고리를 매칭**해준다. 마켓 아이디를 안 넣으면 그 마켓 기준 카테고리 매칭
  자체가 안 됨 — "여러 마켓에 동시 등록할 계획이면 다 넣어라"가 핵심 조언. PTP가 여러 마켓을 동시에
  타겟팅할 때도 "이 배치가 어느 마켓들을 향하는지"를 먼저 알아야 카테고리 매핑(각 마켓 분석 문서의 카테고리
  체계)을 제대로 적용할 수 있다는 같은 원리.
- **카테고리 제외 활용 사례**: 화장품/식품처럼 규제가 까다로운 카테고리를 애초에 제외하고 받는 셀러가 많다 —
  [쿠팡 분석](coupang.md)에서 확인한 "의료기기/건강기능식품은 신고증 소지자만 판매 가능" 규제와 같은 맥락.
  PTP 필터 설계 시 "규제 카테고리 제외" 옵션은 실제 니즈가 있는 기능으로 볼 수 있음.
- **가격 필터의 실제 쓰임새**: 무료배송으로 상품을 올릴 때, 원가가 아주 저렴한 상품(예: 100원짜리 펜)을
  무료배송으로 올리면 배송비를 얹어 부풀린 티가 나서(예: 2,600원) 소비자에게 배송비 바가지로 보일 수 있다 —
  그래서 "일정 가격 이상 상품만" 필터링해서 받는 용도로 가격 필터를 쓴다는 실전 팁.
- **베스트상품 활용법**: "나의 보관함 불러오기"(장바구니처럼 미리 찜해둔 상품만 필터), 그리고 월별 베스트
  상품은 시즌 상품 사전 준비용 — 지금이 7월이면 작년 7월 베스트를 보고 올해 7월 재고를 미리 준비하라는
  식으로 쓰임(단순 "인기순 정렬"이 아니라 "전년 동월 시즌 예측" 목적).

## 결론

이 페이지는 "직접 베낄 양식"이 아니라 **"공급 상품 → 여러 채널 맞춤 데이터 생성"이라는 같은 문제를 실제
서비스가 어떻게 풀었는지 보여주는 설계 참고 자료**다. 마켓별 실제 컬럼 스펙은 여전히 각 마켓 분석
(`coupang.md` 등)을 따로 봐야 하고, 이 문서는 그 위에 얹히는 **필터/설정/저장 UX 설계 참고용**으로만 쓴다.
