# 참고 자료: 샵링커·사방넷·플레이오토 "상품마스터" 구성

**호출 힌트: `/참고-상품마스터-OMS`** — PTP 상품마스터 컬럼을 설계/확장할 때 이 문서를 참고할 것.

## 배경

샵링커/사방넷/플레이오토는 모두 "하나의 공급 상품 정보로 여러 오픈마켓에 동시 등록·관리"하는 멀티채널
OMS(Order Management System)다 — PTP가 Transform(마이그레이션2)에서 만들려는 "상품마스터 → 각 오픈마켓
양식 대응"과 **개념적으로 동일한 문제**를 이미 운영 중인 서비스들이다. [reference-domesin-productdb.md](reference-domesin-productdb.md)가
"공급 상품 → 여러 채널"이라는 같은 구도를 B2B 도매몰 입장에서 보여준다면, 이 문서는 그 반대편(셀러가 직접
상품마스터를 만들어 여러 마켓에 뿌리는 입장)의 참고 자료다.

- 분석 방법: 공개 도움말/가이드북 웹 검색(2026-10-05). **세 솔루션 모두 실제 화면은 로그인 후에만 보이고,
  정확한 엑셀 컬럼 전체 목록은 가입 후 샘플 파일을 받아야 확인 가능** — 아래는 공개 문서로 확인되는 범위
  (카테고리 구조와 일부 대표 항목)까지다. domesin.md는 실제 로그인 계정으로 분석했지만, 이 세 솔루션은
  아직 그 수준의 접근을 못 했다 — 더 정밀한 컬럼명이 필요하면 체험판 가입이 먼저 필요하다.

## 공통 구조 — "마스터 상품" 등록 10단계

세 솔루션 모두 명칭만 다를 뿐 다음 구조로 수렴한다. 샵링커 가이드북이 이 순서를 그대로 명시한다:

1. **상품명**
2. **카테고리** — 내부 분류(마켓별 카테고리 트리에 나중에 매핑)
3. **옵션** — 색상/사이즈 등 조합 + 조합별 재고/추가금액
4. **이미지** — 대표이미지 + 상세이미지
5. **상세설명**
6. **상품 주요정보** — 가격(소비자가/판매가/원가)/브랜드/제조사/원산지/재고 등
7. **검색어/검색필터** — 마켓 노출용 키워드·속성값
8. **상품정보제공고시** — 공정위 법정 고시 항목(카테고리마다 세트가 다름)
9. **배송/반품 정보** — 배송방법·택배사·반품지·반품배송비
10. **대량관리** — 엑셀 일괄등록/수정

## 솔루션별 확인된 사항

### 샵링커(Shoplinker)

**1차 조사(공개 PDF/도움말 기준)**: [가이드북(PDF)](https://www.shoplinker.co.kr/guides/PDF/shoplinker__ver_20240205.pdf) — "마스터 상품"이 공식 용어. 등록 순서가 위 10단계와 그대로 일치. 엑셀 대량등록은 `.xls`(97-2003) 형식 요구. ["쇼핑몰별상품정보관리"](https://help.shopling.co.kr/?no=A00960) — 몰마다 override 가능한 필드 세트(상품명·검색어·정보고시코드·소비자가·판매가·원가·상세설명·재고분할)가 마스터 상품과 별개로 존재.

**2차 심층조사(2026-10-05, `guide.shoplinker.co.kr/guidebook` — 로그인 없이 공개된 Notion 기반 공식 가이드북, 스크린샷으로 실제 화면 확인)**:

- **가이드북 구조**: "2.상품관리"(마스터상품 등록/조회수정, 2페이지뿐)와 "3.상품연동관리"(쇼핑몰 그룹정보관리/쇼핑몰 상품등록/쇼핑몰 상품조회수정, 3페이지)가 분리돼 있다 — **카테고리를 실제 마켓에 매핑하는 작업은 "상품관리"가 아니라 "상품연동관리"(오픈마켓 연동) 쪽에 속한다.** PTP의 "카테고리 매핑" 메뉴 위치를 정할 때 참고할 구조적 근거.
- **카테고리는 3단 구조**(전용 매핑 테이블이 아니다): ① "그룹"(카테고리+배송정책을 묶은 단위, 예: "남성티셔츠/무료배송")에 기본 카테고리가 저장되고, ② 마스터상품 편집 화면에서 **4단 계층 드롭다운**(예: NPLUS/남성의류/상의류/상세분류)으로 "샵링커카테고리"를 고르며, ③ 실제 몰에 연동(등록)하는 시점에 **"①샵링커카테고리 ②고객사(거래처)카테고리 ③선택해제" 중 택1 라디오**로 최종값을 결정한다(그룹별 override도 가능). 즉 "사전에 통째로 매핑해두는" PTP/사방넷/플레이오토식이 아니라 "등록 시점에 표준값 vs 거래처 자체값을 그때그때 고르는" 더 동적인 모델이다.
- **검색어 필드 확정**: 마스터상품 수정 화면 자체에 "키워드(상품약어)" 필드가 있다 — 단, 설명은 "인터파크·인터파크도서·단건몰 연동시 검색 키워드로 등록되는 내용(쉼표구분)"으로, **전몰 공통이라기보다 특정 입점몰 전용 override에 가깝다.**
- **고시정보는 다중 슬롯**: "품목고시" 외에 **"인증정보1~5"로 최대 5슬롯**을 지원한다(품목 코드[예: 01=의류]가 고시 템플릿을 결정하는 구조로 추정). 단일 텍스트 컬럼이 아니라 "슬롯형" 설계라는 점이 플레이오토(아래, 품목정보2~5)와 독립적으로 수렴한다 — 아래 "교차 검증" 참고.
- **가격은 7종이 공존**: 자체(매입처 기준) 시중가/판매가/공급가 3종 + 제휴쇼핑몰(해당 몰 기준) 시중가/판매가/공급가 3종 + 시작가. "공통값 vs 몰별 override"가 가격에서 가장 뚜렷하게 분리돼 있다.
- 출처: `guide.shoplinker.co.kr/guidebook`, `/shoplinkerguide00,02,03,04,05`. ⚠ 이 가이드북 사이트에서 클릭 후 경쟁사(사방넷) 사이트로 무작위 리다이렉트되는 현상이 관측됨(추적/광고 스크립트 의심, 로그인정보 입력은 안 함) — 재방문 시 주의.

### 사방넷(Sabangnet)

**정정(2026-10-05)**: 이전 조사에서 "사방넷(풀필먼트형)"으로 분류했던 `sbfulfillment.co.kr`은 별도 제품이 아니라 **`sabangnet.co.kr`(메인 사방넷, ㈜다우기술)의 "창고관리(WMS)" 서브모듈**이다(양쪽 사이트 footer의 사업자등록번호 220-81-02810/대표이사 김윤덕이 동일함을 직접 확인, sabangnet.co.kr 메인 네비게이션의 "사방넷 WMS 접속" 버튼이 sbfulfillment.co.kr로 연결됨).

**심층조사(2026-10-05)**: `docs.sabangnet.co.kr:1975/sabangnet` — 로그인 없이 완전 공개된 공식 사용설명서(용어사전·메뉴별 안내·FAQ)를 신규 발견. 아래는 전부 이 사이트 원문 기준:

- **카테고리매핑**은 용어사전 표제어로 정확히 존재: "사방넷 카테고리"([카테고리관리], 분류코드 12자리 수정불가)와 "쇼핑몰 카테고리"([쇼핑몰카테고리])를 잇는 사전 매핑 작업. AI 기능으로 "쇼핑몰 카테고리 자동 추천"(2025.04)도 제공 — **PTP의 `category_channel_mappings`(사전에 통째로 매핑해두는 테이블) 모델과 사실상 동일.**
- **검색어 필드 확정**: "사이트검색어"가 용어사전에 정확히 존재("사방넷에 등록한 상품의 검색어 정보"). AI로 "상품 연관검색어 자동 추천"(2024.08)도 지원.
- **고시정보("정보고시")는 마켓별 override 지원**: "쇼핑몰마다 지정된 상품정보고시가 다른 경우 쇼핑몰별로 적용 가능"(전자상거래법 제13조4항 근거 명시). 별도의 "상품정보고시템플릿관리" 메뉴도 있음. AI로 "상품 정보고시 자동 생성"도 지원.
- **배송/반품은 "템플릿 코드" 단위**(상품단위도 거래처단위도 아님): [쇼핑몰부가정보]에서 "부가정보코드"를 한 번 등록해두고 여러 상품에 재사용. "매입처"(공급처)와 "물류처"(출고처)는 완전히 분리된 거래처 엔티티로 각각 별도 월정액 과금(매입처 1,000원/물류처 5,000원, 1개당)까지 있다.
- **출고상품/판매상품 분리가 메인 사방넷에도 존재**: "SKU와 판매상품(연동용 상품)을 매칭"하는 "연결상품매칭" 기능이 메인 쇼핑몰관리 쪽에도 있다 — 즉 "사방넷상품(마스터, 품번코드)" ↔ "SKU/단품(물류단위)" ↔ "쇼핑몰상품(채널, 쇼핑몰상품코드)"의 **3단 구조**이며, 이전에 "풀필먼트 전용"이라 여겼던 개념이 메인 서비스의 일반 구조였다.
- 엑셀 양식 전체 컬럼 헤더는 로그인 벽에 막혀 미확보.
- 출처: `sabangnet.co.kr`, `docs.sabangnet.co.kr:1975/sabangnet`, `sbfulfillment.co.kr/manual/product`.

### 플레이오토(PlayAuto)

**심층조사(2026-10-05)**: `plto.com/customer/HelpDesc/...` 다수 페이지 + 공식 PDF(본문 추출 실패, 구조만 확인). WebFetch 텍스트 확인 기준(화면 캡처 아님, 신뢰도 중간):

- **버전별 용어 차이**: PLTO2.0은 "**마스터 상품**"(기준 1개) → "쇼핑몰 상품"(몰별 N개) 구조. 구버전 EMP는 "상품 기본정보 + **세트**"(세트=판매기간/배송정보/할인율 등이 들어가는 몰별 판매조건 묶음, 겹치는 항목은 세트가 우선) 구조 — 명칭은 달라도 "공통값 + 몰별 override 묶음"이라는 같은 패턴.
- **카테고리는 사전매핑형**: "카테고리 템플릿 관리"에서 내부 분류명+카테고리명을 먼저 만들고 키워드 검색으로 9개 몰(옥션/지마켓/11번가/스마트스토어/쿠팡/롯데ON/카카오톡스토어/토스쇼핑몰) 표준카테고리를 자동매칭 — **사방넷·PTP와 같은 "사전 매핑 테이블" 모델**(샵링커의 "등록시점 택일" 모델과 대비됨). 단, 몰에 "판매중"으로 전송된 뒤엔 카테고리 수정 불가.
- **고시정보는 EMP에서 "품목정보2~5" 슬롯으로 몰별 override**: 카테고리(분류)마다 "상품상세코드" 슬롯의 의미가 다른 특이한 설계(예: [기타재화] 분류에서 상품상세코드 35=모델명). 몰마다 고시 요구가 다르면 품목정보2/3/4/5 탭에 **최대 5세트**를 넣어두고 전송 시 자동 매칭 — 샵링커의 "인증정보1~5"와 **독립적으로 수렴한 "5슬롯" 설계**.
- **배송정보는 공급사(판매자) 단위 공통설정이 원칙**, 그 위에 "세트" 단위 오버라이드가 얹히는 2계층.
- **검색어/검색필터 화면은 이번 조사로 확정 못함**(미해결 — 재조사 필요).
- 대량등록 엑셀 양식이 **기본상품양식/옵션전용/품목정보전용(고시)/카테고리전용/단일상품(스마트스토어)/ESM 등 용도별로 6종 이상 분리**돼 있음 — PTP의 "컬럼별 생성 규칙" 표 하나에 다 섞는 방식과 가장 대비되는 사례.
- 출처: `plto.com/customer/HelpDesc/gmp/14425,564,14429,13270,14658,13832,15004,16234,14989,1930`, `plto.com/customer/HelpDesc/emp/18,555,472,359`, 공식 PDF(`cloud.plto.com/plto20/download/guide/PLAYAUTO2.0_product_guide.pdf`, 본문 미추출).

## PTP 참고용 — "메뉴 수준" 전체 지도 (2026-10-05 추가)

**이 섹션의 목적이 바뀌었다는 점을 먼저 적어둔다(사용자 지시, 2026-10-05)**: 애초 이 문서는 "상품마스터
컬럼 하나하나가 뭐가 빠졌는지"를 보려고 만들었다. 하지만 사용자가 세 솔루션을 분석하라고 한 진짜 이유는
"PTP도 결국 각 오픈마켓에 상품을 등록·관리하는 같은 목적의 도구이니, 컬럼 단위가 아니라 **메뉴/기능 단위로
세 솔루션의 장점을 참고해서 PTP에 들여올 기능을 판단**하기 위함"이었다. 그래서 이 섹션은 컬럼이 아니라
**메뉴 구조 전체**를 대조한다 — 앞으로 PTP에 새 기능을 고민할 때 "이 세 솔루션엔 이걸 어떻게 하고 있지?"를
먼저 찾아보는 1차 참고자료로 쓸 것.

### 세 솔루션의 전체 메뉴 구조 (상품등록·관리 범위만, 조사 기준)

| 솔루션 | 메뉴 대분류 | PTP와 관련된 하위 메뉴 |
|---|---|---|
| 샵링커 | 1.기본정보관리 | 쇼핑몰 등록관리(입점계정/API키 — 몰 1곳에 **복수 로그인ID 등록** 가능) |

### 스코프 경계 — 의도적으로 참고 대상에서 제외한 것

세 솔루션은 **풀 OMS**(주문수집, CS/클레임, 정산, 통계, 창고관리/WMS, 메시지발송까지)지만, PTP의 미션은
"공급 데이터 수집 → 상품마스터화 → 오픈마켓 등록"까지다. 아래는 조사는 했지만(메뉴 존재는 확인) **PTP가
들여올 범위가 아니라고 판단**해 더 깊이 보지 않은 영역이다 — 나중에 PTP가 주문/CS/정산까지 다루게 되면 그
때 이 문서의 교육자료/매뉴얼 링크(샵링커 "4.주문연동관리/5.고객CS관리", 사방넷 "주문관리/C·S관리/정산관리/
통계분석/창고관리", 플레이오토 주문 관련 메뉴)로 돌아와 다시 조사하면 된다:

- 주문수집/주문관리, CS/클레임 관리, 정산관리, 통계분석, 창고관리(WMS)/재고 실물관리, 대량 메시지발송(알림톡 등)

## 교차 검증 — 세 솔루션이 독립적으로 수렴한 패턴 (2026-10-05)

세 솔루션을 각각 별도로 심층조사했는데도 아래 패턴들이 **서로 짠 것처럼 똑같이 등장**했다 — 우연이라기보다 "멀티채널 상품마스터"라는 문제 자체가 요구하는 구조로 봐야 한다:

1. **고시정보의 "다중 슬롯" 설계가 2/3 솔루션에서 독립적으로 등장**: 샵링커 "인증정보1~5", 플레이오토 EMP "품목정보2~5" — 둘 다 "최대 5개"라는 숫자까지 비슷하다. 사방넷도 "쇼핑몰별로 다른 고시 적용 가능"으로 동일 필요성을 확인. → PTP가 §2에서 "고시정보는 상품마스터 컬럼이 아니다"라고 결론 낸 것 자체는 유지하되(여전히 상품마다 다른 값이 아니라 "몰마다 다른 템플릿"이 다른 것), **"몰마다 다른 고시값"을 담을 그릇(슬롯/override 구조)이 PTP엔 아직 없다**는 게 새로 확인된 간극이다.
2. **가격/검색어/상품명도 전부 "공통값 + 몰별 override" 패턴**: 샵링커 가격 7종, 사방넷 "사이트검색어"(공통이라기보다 몰별 느낌), 샵링커 "키워드(상품약어)"(인터파크 계열 전용 느낌) — PTP의 §7-3 열린 질문 ①("마켓별 override 값 분리")이 세 솔루션 모두에게 확인된, 가장 강한 신호의 공백이다.
3. **카테고리는 "사전 매핑형"(사방넷·플레이오토·PTP)과 "등록시점 택일형"(샵링커)으로 갈린다** — 다수(2/3)가 PTP의 현재 모델(`category_channel_mappings`)과 같은 방향이라, §6의 Option B(엑셀 연결) 설계를 바꿀 필요는 없어 보인다. 다만 샵링커식 "거래처 자체 카테고리 override"는 PTP에 없는 개념이라 §7-3 ①과 겹쳐 같이 고려할 거리다.
4. **출고/재고 단위와 판매/노출 단위의 분리**(§7-3 ②)가 사방넷은 메인 서비스 레벨(3단: 마스터↔SKU↔쇼핑몰상품)에서, 플레이오토는 EMP "세트" 개념에서 각각 확인돼 — 1개 솔루션만의 특이사례가 아니라는 근거가 보강됐다.

## PTP 설계에 주는 시사점

1. **검색어/검색필터가 PTP 상품마스터에 없다** — 세 솔루션 모두 독립 카테고리로 다루는데 PTP는 아예 컬럼이 없다. 가장 확실한 공백(메인 설계 문서 §2/§3 참고).
2. **"공통값 vs 마켓별 override" 분리**(샵링커) — PTP 상품마스터는 모든 마켓에 같은 값을 낸다. 당장 급한 건 아니지만 향후 "마켓마다 다른 상품명/가격"이 필요해지면 설계가 바뀌어야 한다.
3. **"재고단위 vs 노출단위" 분리**(사방넷) — 묶음/박스단위 공급이 흔한 도매몰 스크래핑 특성상, PTP도 언젠가 필요할 수 있는 구분.
4. **기본정보와 부가정보(옵션/이미지/고시/배송)의 화면 분리**(플레이오토) — PTP Transform의 "컬럼별 생성 규칙" 표가 전부 한 화면이라 TO-BE 컬럼이 많아지면(지금 실사용 예시가 90개) 다루기 번거로울 수 있다는 신호.

## 결론

세 솔루션 모두 "상품마스터"를 PTP와 같은 목적(여러 마켓 공용 기준)으로 쓰고 있고, 구조도 거의 동일하다 —
이건 PTP가 지금 하려는 설계 방향이 업계 표준과 어긋나지 않는다는 뜻이다. 다만 공개 문서만으로는 "정확한
컬럼명/개수"까지는 못 얻었다 — 더 정밀한 비교가 필요하면 체험판 가입 후 실제 샘플 엑셀을 받아 이 문서를
갱신하는 게 다음 단계다.
