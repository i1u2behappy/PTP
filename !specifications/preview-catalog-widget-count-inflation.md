# 미리보기 카테고리 개수가 실제보다 크게 부풀려지던 문제 (위젯 오염)

## 배경

펫투비(site 11, 고도몰) 전체 스크랩 실행 중 미리보기가 집계한 총 개수(3902개)와 실제 수집된 개수(1448개)가
크게 어긋난다는 문제가 발견됐다. 처음엔 반대로(실제 수집 쪽이 축소 집계) 의심했으나, 실제 몰 페이지를
직접 확인해 원인이 미리보기 쪽에 있음을 확정했다.

## 조사

previewCatalog가 카테고리 개수를 구하는 순서: ① "총 N개" 문구 → ② 페이지네이션 위젯 → ③ 지수+이분
탐색 → ④ 직접 순회(최후수단). 19개 카테고리 중 15개는 ①로 해결돼 정확했고(실제 수집과 100% 일치 —
사료 21, 배변용품 44, 목욕용품 44 등), 문구/위젯이 없어 ③·④까지 간 4개 카테고리(간식 1276, 미용용품
702, 장난감/훈련용품 678, 고양이간식 809)만 실제(각각 526/102/178/205)보다 15~41%로 부풀려져 있었다.

"강아지 > 미용용품"의 실제 몰 페이지(`?category=031003&page=2`)를 쿠키 유지한 채 직접 열어 확인: 진짜
상품 링크(`goods_view.php?goodsno=`)는 0개였다(페이지에 있는 "goodsno" 문자열은 전부 장바구니/최근본상품
위젯의 자바스크립트 코드). 즉 이 몰은 `page=N` 파라미터 자체가 안 통한다 — previewCatalog가 "새
페이지"로 오판한 것은 실제로는 위젯이었다.

원인은 `lib/scraper.ts`의 `countProductsOnPage`/`countProductsFromHtml`(둘 다 previewCatalog가 씀)와
`scanForProducts`(실제 수집이 씀) 세 함수 모두 platformSel 경로(고도몰 `.item_cont a, .goods_list a`)에는
"최근 본 상품"류 위젯 제외 로직이 전혀 없었다는 것 — 폴백 경로에만 카페24 전용 `productrecent` 제외가
있었다(펫투비는 고도몰이라 애초에 폴백을 안 탐). 위젯이 platformSel과 같은 클래스를 공유해 매 요청마다
살짝 다른 상품(최근 조회 이력이 누적됨)을 보여주면, 지수 탐색/직접 순회가 "새 페이지가 계속 나온다"고
오판해 개수가 한없이 부풀려진다.

## 수정

`lib/scraper.ts`:
- `WIDGET_CLASS_EXCLUDE_SRC` 상수 추가(`productrecent|recent-?list|recent-?view|recently-?viewed|recommend`)
  — 카페24/고도몰 등 여러 몰의 "최근 본 상품/추천 상품" 위젯 클래스명을 포괄.
- `countProductsOnPage`(브라우저), `countProductsFromHtml`(cheerio/HTTP), `scanForProducts`(실제 수집)
  세 함수 모두 userSel을 제외한 모든 경로(platformSel + 폴백)에 이 위젯 제외를 적용(조상 요소 class를
  정규식으로 검사 — cheerio-select의 속성선택자 `i` 플래그 지원에 의존하지 않도록 기존 폴백과 같은
  방식 유지).
- 부수적으로 `collectFromListing`의 다음 페이지 이동(15초 타임아웃)이 실패해도 조용히 무시하고 바로
  스캔하던 부분에, 실패 시 30초로 한 번 더 재시도하는 안전장치를 추가(collectFromListing이 이 사고의
  원인이라는 초기 가설은 이후 조사로 기각됐지만, 이 재시도 자체는 해롭지 않은 방어적 개선이라 유지).

## 상태

**구현 완료.** tsc/eslint 클린. "미용용품" 카테고리는 실제 몰 페이지 확인으로 위젯 오염을 직접
검증했다. 나머지 3개 카테고리(간식/장난감·훈련용품/고양이간식)는 실제 수집 결과가 "총 N개" 카테고리들과
같은 배율로 정확히 들어맞는 정황 증거(437 + 526+102+178+205 = 1448, 실제 수집 총량과 정확히 일치)로
같은 원인으로 추정하나 개별적으로 라이브 재검증하지는 않았다. 수정 이후 이 몰을 다시 미리보기해서 총
개수가 실제(1448 근방)로 나오는지는 다음 사용 시 확인 필요.
