# 스크랩 미리보기 그리드 — 컬럼 구성 개편 (2026-07-29)

## 배경

사용자가 스크랩 미리보기 화면에서 "공급가 컬럼이 안 보인다"고 지적 — 조사해보니 `cost_price`는
`lib/extract.ts`가 "도매가/공급가" 라벨을 찾아 정식으로 추출하는 실제 필드이고, "스크랩 대상
직접지정"(`lib/scraper.ts`의 `CANONICAL_FIELDS`)에는 이미 고정 필드로 등록돼 있었는데, 정작
`ScraperPanel.tsx`의 미리보기 그리드(`PreviewProduct` 타입 + 테이블 컬럼)에는 애초에 빠져 있었다 —
의도된 설계가 아니라 컬럼 추가 누락이었다.

## 변경 내용 (`components/panels/ScraperPanel.tsx`)

여러 차례 요청을 거쳐 최종 컬럼 순서:

카테고리 → 소비자판가 → 공급가 → 브랜드 → 제조사 → 원산지 → 옵션1 → 옵션2 → 재고 → 대표이미지 →
상세이미지 → 상품요약정보 → 영문상품명 → (실제 옵션명 기준 동적 컬럼, "option1"/"option2"라는 영문
그대로인 것은 제외) → (🎯 스크랩 대상 직접지정으로 지정된 커스텀 필드)

- `PreviewProduct` 인터페이스에 `cost_price: number | null` 추가.
- "가격" 헤더를 "소비자판가"로 바꾸고 바로 옆에 "공급가" 컬럼 추가(`₩` 포맷, 없으면 `-`).
- "옵션1"/"옵션2" 고정 컬럼을 원산지 뒤에 추가 — `options[0]`/`options[1]`의 값을 위치 기준으로
  보여준다(옵션명과 무관하게 항상 "첫 번째/두 번째 옵션").
- "옵션별 재고" 컬럼 제거(`stock_by_option` 미사용).
- "대표이미지"/"상세이미지"를 "재고" 컬럼 바로 뒤로 이동.
- 테이블 끝의 동적 옵션 컬럼(`options.map(o => o.name)`)에서, 옵션명이 영문 그대로 "option1"/
  "option2"(대소문자 무관)인 경우만 필터링해 제외 — 위 고정 옵션1/옵션2 컬럼과 중복 노출을 피하기
  위함. 3번째 이후 옵션이나 제대로 된 이름(색상/사이즈 등)은 그대로 노출된다.

## 검증

`npx eslint`/`npx tsc --noEmit` 통과. `cost_price`는 API 응답(`/api/scrape/preview`,
`/api/scrape/preview-catalog`)에 이미 포함돼 있던 값이라 백엔드 변경 없이 프론트엔드 렌더링만
수정했다 — 기존에 스크랩된 다른 몰 데이터나 "스크랩 Raw 확인" 그리드(`StagingItemsGrid.tsx`, 이미
공급가 컬럼 보유)에는 영향 없음, 재스크랩 불필요.

## 컬럼 구성이 기준 마스터테이블 등록 순서를 그대로 따르도록 전면 재작성 (2026-08)

위 컬럼 순서는 이후 하드코딩 자체가 문제로 지적되어 완전히 대체됐다 — 이제 컬럼 라벨·순서·존재 여부
전부 `master_schema_fields`(기준 마스터테이블관리) 등록 내용을 그대로 따른다. 자세한 설계와 다른
화면들(스크랩 검토 그리드/상품마스터 목록·상세/가격 및 이익 관리/피커)에 동일하게 적용한 내용은
[[master-table-driven-column-consistency]] 참고. `/api/scrape/preview`(단일 상품용 구 엔드포인트)는
이 세션 중 유일한 호출부(`refreshPreviewSingle`)가 없어지면서 고아가 돼 함께 삭제됐다.

## "상품정보고시 전체"/"그 외 자동 스캔된 정보"의 중복 표시 제거 (2026-08)

사용자 지적: 두 텍스트 블록의 내용이 서로 겹치고, 위 컬럼(카테고리/브랜드/제조사/원산지/가격류 등)에
이미 나온 값도 다시 나온다. 원인은 두 가지:
- `extra_info`(상품정보고시 전체)는 상품정보고시 표의 모든 라벨을 그대로 다 보여주고, `custom_fields`
  (그 외 자동 스캔된 정보)는 그중 이미 전용 필드로 뽑힌 라벨(`CLAIMED_INFO_LABEL_RE`, brand/manufacturer/
  origin/가격류 등)만 뺀 나머지인데 — `custom_fields`는 결국 `extra_info`의 부분집합이라 "상품명"/
  "구매방법"/"배송주기"처럼 그 정규식에 안 걸리는 라벨은 두 곳에 똑같이 나왔다.
- `extra_info` 자체가 카테고리/상품명처럼 이미 위 컬럼으로 보여주는 값의 원본 라벨도 필터 없이 그대로
  포함하고 있었다.

`ScraperPanel.tsx`에서 두 단계로 수정(둘 다 화면 렌더링 시점 필터일 뿐, `extra_info`/`custom_fields`
데이터 자체나 `lib/extract.ts`는 안 건드림 — `extra_info`는 "몰 구조 파악"의 `infoLabels` 수집에도
쓰여 그 필드까지 좁히면 다른 기능에 영향):
1. "그 외 자동 스캔된 정보"는 `extra_info`에 이미 나온 라벨과 겹치면 제외.
2. "상품정보고시 전체"는 위 컬럼에 실제로 표시 중인 라벨(기준 마스터테이블 라벨, 동적)과 겹치거나
   `CLAIMED_INFO_LABEL_RE`(브랜드/가격류 등 동의어)에 걸리면 제외 — `lib/extract.ts`의 그 정규식을
   그대로 복제해 클라이언트 컴포넌트에 둠(그 파일은 Playwright 의존 서버 전용 코드라 import 대신 복제,
   둘 중 하나를 고치면 같이 맞춰야 함).

## 탭 전환 시 미리보기 결과도 같이 복원 (2026-08)

`Workspace.tsx`가 탭 전환마다 비활성 탭을 완전히 언마운트하는 구조라, 예전엔 폼 입력값(몰 선택/URL/
카테고리 목록, `FORM_STATE_KEY`)만 localStorage로 복원하고 미리보기 **결과**는 "다시 눌러서 확인하면
되니 저장하지 않는다"고 일부러 뺐었다. 사용자가 "스크래핑 미리보기한 데이터도 타 메뉴로 가더라도
다시 스크래핑 메뉴로 돌아오면 데이터 보이게 해"라고 요청해 그 결정을 뒤집었다 — `FORM_STATE_KEY`
저장/복원 대상에 `previewResult`/`previewTotal`/`previewItems`/`detectedPlatform`을 추가, 몰 변경 시
기존처럼 함께 초기화된다.
