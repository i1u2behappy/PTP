# 스크랩 검토 화면 — 확정 상태 표시/정렬 + 되돌리기 + 그룹별 일괄선택

## 배경

펫투비 스크랩 검토(1448건) 도중 세 가지 요청이 있었다: ① 확정/미확정 상태를 그리드에서 쉽게 찾아
정렬/필터할 수 있어야 함, ② 이미 확정(merged)된 항목을 다시 미확정으로 되돌릴 방법이 없음, ③ 확정/
미확정 항목을 각각 따로 일괄선택할 수 없음(기존엔 "전체 선택"이 미확정 항목만 대상으로 동작).

## 수정 1 — "확정여부" 컬럼 고정 + 이름 변경

`components/panels/shared/StagingItemsGrid.tsx`: 기존 "마이그레이션 상태" 컬럼(`migration_status`)이
기본 컬럼 순서 맨 끝에 있어 찾기 어렵다는 지적 — 체크박스 바로 옆(맨 앞)으로 옮기고 이름을 "확정여부"로
바꿨다. 첫 번째 컬럼은 위치 기반으로 sticky 처리되므로 가로 스크롤해도 항상 보인다. 기존 사용자의
저장된 컬럼 순서(`localStorage`)는 위치 변경이 자동 반영되지 않아(새로 추가된 키만 뒤에 붙는 구조)
저장 키 버전을 올려(`stagingGrid.colOrder.v9` → `v10`) 한 번 리셋했다(이전에도 같은 이유로 v8→v9
리셋이 있었던 선례를 따름).

## 수정 2 — 확정 → 미확정 되돌리기

이미 확정(merged)된 항목을 되돌릴 때 연결된 `mall_products`/상품마스터 데이터(다운로드된 이미지 포함)를
어떻게 할지 사용자에게 직접 확인했다 — "staging 상태만 되돌리기"(추천안)를 선택받았다: 실제 상품
데이터는 그대로 두고, 나중에 다시 확정하면 최신 스크랩값으로 덮어쓰는 방식이 더 안전하고 되돌리기도
쉽다는 이유.

- `lib/scrape/staging.ts`: `unmergeStagingItems(ids)` 추가 — `scrape_staging_items.status`를
  `merged→pending`으로만 되돌리고(`WHERE status='merged'` 조건으로 안전하게 제한) 그 외 테이블은
  건드리지 않는다.
- `app/api/scrape-staging/unmerge/route.ts`: 신규 API(`mergeStagingItems`의 API 패턴과 동일).

## 수정 3 — 확정/미확정 그룹별 일괄선택

`StagingItemsGrid.tsx`: 기존엔 `status==='pending'`인 행만 선택 가능했고(이미 확정된 행은 체크박스
비활성화), "전체 선택" 하나만 있었다. 이제 `merged` 상태 행도 선택 가능해졌고(되돌리기 대상), "미확정
전체선택"/"확정됨 전체선택" 체크박스를 각각 독립된 `<label>`로 분리해 뒀다(하나의 `<label>`에 체크박스
두 개를 같이 넣으면 라벨 텍스트 클릭 시 첫 번째 체크박스가 대신 토글되는 사고 패턴이 이 그리드 헤더에서
과거에 있었음 — 재발하지 않도록 처음부터 분리). "확정" 버튼은 선택된 미확정 항목만, "↩️ 미확정으로
되돌리기" 버튼(확정된 항목을 하나라도 선택했을 때만 노출)은 선택된 확정 항목만 대상으로 동작해, 두
상태를 섞어 선택해도 각 버튼이 알아서 해당 분만 처리한다. `skipped`(건너뜀) 행은 어느 쪽 대상도
아니라 계속 선택 불가로 남는다.
